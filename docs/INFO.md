# Launch Gate - платформа для проведения конкурсов и хакатонов
Платформа нужна организаторам, чтобы быстро запустить конкурс, собрать участников, сформировать команды, настроить этапы, принять проектные работы, проверить их с экспертами и выгрузить результаты.
организатор не должен собирать конкурс из Google Forms, Excel, Telegram, Google Drive и ручных протоколов. Все основные процессы конкурса должны быть в одном месте.

## Возможности платформы

### Основные роли
Есть две основные роли - организаторы и участники. Организаторы имеют несколько подролей

### Регистрация
Пользователь может зарегистрироваться как организатор или участник

**Регистрация участников**
Пользователь вводит почту, пароль, у каждого участника есть уникальный id платформы
В карточке он может заполнить:
- ФИО
- указать Telegram или другой контакт. Будет три вида контактов которые будут расширяться: Telegram, Вконтакте и почта
- никнейм
- информация о себе 

**Регистрация организаторов**
Регистрация проходит аналогично участникам, только храним информацию о том, что это аккаунт организатора

### Роли организаторов
- Creator: Создатель конкурса - может делать все в конкурсе
- Admin: Creator может назначать администраторов. Они также имеют доступ ко всему и делают что хотят
- Expert: Проверяет работы участников. Умеет: видеть работы, открывать карточки проектов, смотреть материалы, ставить оценки, оставлять комментарии, видеть свои завершенные/незавершенные проверки
- Mentor/Tracker: Может: видеть назначенные команды, смотреть прогресс, оставлять рекомендации и комментарии у проектов команд, видеть сдачи команды, помогать командам до финальной оценки, выбирать время звонков с командами (можно сказать управлять календарем, который видят участники)

### Создание конкурса организатором
Организаторы типа Admin могут создать конкурс и настраивать его базовую структуру.
- название конкурса;
- описание;
- даты проведения;
- формат участия: индивидуально или в командах;
- минимальный и максимальный размер команды;
- правила конкурса;
- контакты организаторов;
- ссылки на различные чаты;
- ресурсы для участников: документы и тд;
- статус конкурса: черновик, опубликован, идет, завершен.

После нажатия на кнопку опубликовать конкурс начинает работу

**Создание этапов и чекпоинтов**
Организатор может выбрать, конкурс будет идти в один этап или несколько этапов (поинтов)
Многие конкурсы проходят не в один этап, а через несколько чекпоинтов. Например:
- идея;
- исследование;
- прототип;
- финальная сдача;
- защита.

Организатор должен уметь создать этапы и настроить для каждого этапа:
- название;
- описание;
- дедлайн;
- правила этапа;
- доп информация;
- ресурсы для этапа;
- кто проверяет;
- критерии оценки;
- проходит ли команда дальше после этапа.

Логично, что если этап один, то весь конкурс проходит в один этап. Если несколько этапов то каждый из них по сути это мини конкурс

**Форма заполнения проекта участников**
Для каждого этапа организатор может настроить данные, которые должен отправить участник или команда. Например:
- бизнес план
- презентация
- документы
- ссылка на код
- ссылка на видео
- видео или фото
Таким образом организатор должен уметь гибко настраивать такие поля, которые могут иметь разные типы.

**Критерии**
Организатор может внести для каждой формы проекта участников критерии проверки. Они используются для четкого структурирования того, что хочет получить организатор в качестве работ участников.
Обычно там указываются форматы отправляемых работ, что должно быть указано в том или ином поле. Рекомендации для проверки эксператами и другая информация необходимая для оптимальной проверки работ.

### Проверка работ
Эксперты должны проверять работы участников:
- один эксперт может проверять несколько работ
- каждый проект после проверок содержит оценки от экспертов. Нужно это обыграть визуально красиво
- при проверке экспертом проект помечается у него как черновик. Только если он нажмет сделать итоговую оценку - проект будет оценен им. 

**ai проверка**
Будет добавлен ai агент для первичной проверки работ. Он следует критериям оценки формы и делает первчиную проверку по ним. Указывает что точно не так, где есть вопросы, производит первчиную оценку с подробным описанием проблем
Кроме этого он может суммаризировать работу участника, быстро объяснять суть его проекта. 

### Ментор
Ментор закрепляется за командой участников. Организатор сам закрепляет каждого ментора за командами.
Ментор может:
- видеть список команд
- заходить в каждую команду, видеть участников и заполненные ими формы
- может оставлять комментарии (как ревью в гитхаб для каждого поля формы)
- он также имеет доп функционал: time managment команд. У него есть отдельная таблица или списко в виде календаря где он может назначить созвоны с командами. То есть для команды он выбирает время , в проекте команды отображается ближайший созвон с ментором. Они также могут видеть расписание созвонов

### Участники и команды
Участник в своем профиле видет свои данные, может их менять
Кроме этого он имеет вкладку история проектов, то есть его портфолио. Сначала он видет активные проекты, то есть в скоторыми он участвует в конкурсах, а ниже его прошлые проект по убыванию даты
Он может провалиться в проект:
- если активный, то видит команду и рабоатет над проектом
- если прошедший, то там есть информация но редактировать ее он не может

**Регистрация на конкурс**
Конкурс может быть одиночным и командым
Если он командный:
- участник видит всех остальный зареганых участников
- видит все команды которые уже существуют
- может отправить запрос на присоединение в команду
- может создать свою команду и стать лидером

Лидер команды может отправлять приглашения другим участникам, либо отправить ссылку (генерируется) на присоединения в команду. Он может отправить ее куда угодно, чтобы другой человек вошел в его команду
Только лидер может публиковать итоговое решение проекта

### Выгрузка работ
Организатор может выгрузить оценки работ участников или даже краткие описания работ. Их можно выгрузить в excel в csv и других форматах. они выгружаются как в других конкурсных платформах. 
Нужно иметь несколько популярных шаблонов для выгрузки работ. 
Кроме этого органиазотор может сам задавать формат выгрузки, а ai агент адаптирует данные под данный формат и выгружает их
