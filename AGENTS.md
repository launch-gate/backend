# Project context (read first)

## Goal
Общая цель - разработка новой платформы для проведения конкурсов и мероприятий
Цель для данного проекта - разработка системы на Spring Cloud (бэкенд приложения). Система будет состоять из нескольких микросервисов

## Services
Сервисы инфраструктуры Spring Cloud лежат в папке infrastructure:
- config-server: загрузка конфигураций из git репозитория с конфигурациями
- discovery-server: Eureka discovery server
- api-gateway: маршрутизация запросов
Микросервисы бизнес логики лежат в папке services:
- identity-service: управление пользователями системы
- competition-service: логика, связанная с содзданием и управлением самих соревнований
- participation-service: логика участия в сорвенованиях, разделение на команды, приглашения в команды, организация команд и агрегация участников
- projects-service: информация о проектах польхователей в рамках портфолио или в рамках соревнований
- expert-service: логика для проверки и выгрузке работ участников со стороны эксрпертов
- files-service: отдельный сервис для работы с файлами в minio


## Configuration
Все конфигурации yaml лежат в репозитории https://github.com/launch-gate/launch-gate-config-repo.git
Структура:
Для каждого сервиса есть общий yaml и локальный. 
Общие:
- application.yaml
- api-gateway.yaml
- identity-service.yaml и другие 
Локальные (для разработки локально на своем компьютере)
- application-local.yaml
- api-gateway.yaml
- identity-service.yaml и другие
При создании нового микросервиса, нужно также для него создать yaml файлы в данном репозитории.

## Technology
Разработка ведется на Java 24, Spring boot 3.5.1, Spring Cloud 2025.0.1

## Conventions
- разработка с использованием микросервисов Spring Cloud
- у каждого микросервиса своя база данных
- код должен быть архитектурно понятен, прозрачен. Использовать подходящие паттерны при написании системы
- общие DTO для двух микросервисах могут дублироваться в каждом микросервисе, отдельный модуль или генерацию создавать не нужно


## Work
При написании кода нужно смотреть в папку progress в корне проекта. В данной папке лежат файлы с именами вида: 22-02-2026-progress. Файлы расширения md. Каждый файл хранит прогресс по разработке в разные даты. Необходимо смотреть файлы, чтобы понимать прогресс по проекту 
В папке docs будут лежать данные о самом проекте, его документация, схемы бд, дополнительная логика и описание. В каждом микросервиса также будет папка docs в которой будет храниться документация
